## What the public surface already provides

The [scoring entry point](../../bindingmt/score.py) evaluates one prepared
conformation and returns a detached pose. The
[adapter](../../bindingmt/engines/_vina_scoring.py) rejects geometry/state/name
conflicts before native setup and retains actual submitted inputs, settings,
references, prior scores and new histories. Two calls and a serial loop suffice
when each original pose already has a matching prepared problem. No additional
batch API is established as necessary by this review.

The public [pose/result operations](../../bindingmt/core/results.py) supply
reconstruction, persistence and conservative ranking. Their boundaries matter:

- `to_molecular_system(source)` requires a verified map and delegates copying,
  extraction and coordinate assignment to MolSysMT. It returns a molecular
  system, not an automatically received new scoring preparation.
- `prepare_ligand(...)` consumes the declared chemistry/mechanics and torsion
  choices. Composition after pose reconstruction is a candidate to receive,
  not a demonstrated defect or a reason to implement another molecular tool.
- `rank_by` conserves its exact-context/state contract. Distinct valid input
  hashes do not become identical after chemical correspondence is received.
- `ranking_history` describes actual backend/public ranking decisions. A study
  report cannot be inserted as a fictitious `rank_by` decision.

The [existing scoring inspection example](../../examples/inspect_saved_scoring.py)
reads and audits saved records; it deliberately does not prepare, rescore,
compare or order them. The [new public usage guide](same_state_rescoring_workflow.md)
exposes current calls and these limits without asking a user to run qualification
supervisors, adapt frozen case roots or import private implementation helpers.
It is source-reviewed documentation, not a newly executed workflow acceptance.

## Concrete next receiving boundary

Receive one maintained example of the following actual user task under #78:

1. Start from a declared complete prepared source and its existing scored
   `DockingResult`, preserving the original result and ranking decisions.
2. For each intended pose, compose public molecular reconstruction and explicit
   preparation with the correct source/native/written axes. Verify nonmutation,
   geometry, charges/types/assignments, maps and declared torsions. Preserve all
   failures and unsupported cases; do not infer missing historical chemistry.
3. Add two distinct named evaluations through public `score(..., pose=...)` and
   save each completion. Retain original scores/ranks/IDs/observations alongside
   the new records. Receive detached JSON and collection-level audits without
   inventing collection stages.
4. Define how the user requests the justified study comparison and obtains an
   admitted report or a reasoned refusal, with actual input identities, units,
   method/reference/preparation evidence and saved decision history. Keep the
   strict `rank_by` route intact. Decide explicitly whether this profile uses a
   separate study report rather than pose ranks.

Prefer an existing supported public composition. If this concrete task reveals
a repeated missing BindingMT record/admission operation, design only that small
operation with its inputs, outputs, refusals and persistence contract. Molecular
tools remain provider-owned. Do not turn the finite notebook reader into a
generic API by removing its trusted roots or hard-coded case checks, or require
users to manufacture qualifying evidence. A new framework, universal state
identity, automatic score calibration or broad campaign model is not authorized
by these observations.

The ordinary route should keep common operations brief and make failures
actionable. The deeper route should expose the same scientific objects,
evidence, assumptions and explicit choices rather than a second inconsistent
API. Actual walkthrough receiving and user review remain separate from this
design intent and from measured performance. Public release/matrix work stays
#30/#47; provider-wide contracts, E1–E5 and E4 scheduling retain their owners.
