# Developer onboarding and machine handoff

## What

The maintainer requests a guide from which a new developer can join and continue
on another machine without reconstructing the chat. The same repository and
issue identities remain; the initial mention of moving repositories was corrected.
The previous autonomous implementation goal was paused/cleared; this is a
documentation handoff, not renewed scientific execution.

## How

Review the entry route, real source map, current plan/owners, setup and evidence
custody. Update maintained guidance, preserve dated producers and distinguish
current instructions from historical checkpoints. Verify links, report lifecycle,
administrative controls and final resource/publication declarations.

## Why

Inspection at `8e65091a0002023527ed7d3d6754a50695d2e1bd` finds a 434-line entry
page with its actual reading order buried under update history; a current
roadmap that still describes E4 receiving as nonpassing; strategy that still
forbids Extended work; a conceptual source tree presented without an implemented
map; delivered Viewer #291 callbacks still listed as missing; stale route counts;
and a link to an audit report already moved to archive. Ignored SDKs/private
artifacts and machine-specific prefixes need explicit fresh-clone/custody routes.

## What was refuted

No runtime defect or new molecular capability is established by this review.
No new scientific experiment, source-provider upgrade, package release, renamed
repository or issue transfer is needed. Rewriting historical observations or
copying Conda prefixes cannot establish a qualified new installation.

## Scope and exclusions

Maintain documentation and its navigation. Preserve frozen scientific inputs,
test-support snapshots, source/artifact identities and provider ownership.
MolSysMT retains all general molecular work. Actual artifact transfer and setup
on the destination machine are separate actions and must not be claimed here.

## Acceptance criteria

- The first-reading route explains purpose, concepts, decisions, source and tests.
- The handoff identifies the actual checkpoint, unfinished investigation,
  accepted product scope, owners, deferrals and next meaningful actions.
- A fresh clone has documented environment/SDK acquisition and clear editable,
  normal-source and public-artifact qualification distinctions.
- Git-contained evidence and externally retained artifacts/custody are explicit;
  no historical temporary prefix is silently required.
- Current status contradictions and maintained broken links are corrected while
  original evidence remains intact.
- Link/index and applicable administrative/resource/publication checks pass;
  the exact delivery/CI scope and any pending evidence are reported honestly.
